# 오류 분석

평가셋: 개발셋 40문항(`questions.jsonl`: RAG 30 · 도구 8 · 범위 밖 2), 홀드아웃 12문항(`holdout.jsonl`: RAG 12).
모든 수치는 오프라인 모드(규칙 라우터 + 문장 발췌)에서 측정했다. 원자료는 `results/*/per_question.jsonl`에 있다.

## 1. 한국어 질문과 영문 문서 사이의 검색 누락 → 용어사전 hybrid로 해결

**증상.** e5 dense 검색만 쓰면 개발셋 30문항 중 4문항이 top-4 안에 정답 문서를 하나도 가져오지 못했다(Hit@4 0.87).

| ID | 질문 핵심어 | dense top-1 | 원인 |
|---|---|---|---|
| q13 | 시크릿·하드코딩 | CSRF Cheat Sheet | 업계 음차어가 영어 임베딩 공간과 잘 정렬되지 않음 |
| q19 | 허용 목록·차단 목록 | Top10 A03 | 번역어("허용 목록")와 원문("allowlist")의 표현 차이 |
| q22 | 접근 통제 기본 원칙 | Top10 A04 | "deny by default"라는 고유 표현을 못 잡음 |
| q29 | 크리덴셜 스터핑 | CSRF Cheat Sheet | 음차어 |

**조치.** 한→영 보안 용어사전 51개(`agent/glossary.py`)로 질의를 확장하고,
`score = dense + 0.3 × TF-IDF(확장 질의)` 형태의 hybrid 검색을 만들었다.

**결과.** 개발셋 Hit@4 0.87 → **1.00**, MRR 0.82 → **0.95**.

**과적합 점검.** 용어사전은 개발셋 오류를 본 뒤에 만들었으므로 개발셋 점수는 낙관적이다.
그래서 튜닝을 끝낸 **다음에** 홀드아웃 12문항을 새로 작성해 한 번만 평가했다.
홀드아웃에서도 Hit@4는 0.83 → **0.92**로 개선이 유지됐다.
다만 12문항이라 한 문항이 8.3%p에 해당해서, 통계적으로 확실한 차이라고 말하기는 어렵다.

## 2. 크고 일반적인 문서가 검색 결과를 차지하는 문제(hub 문서)

CSRF Cheat Sheet는 조각이 122개로 가장 많고, 토큰·쿠키·세션 이야기를 두루 다룬다.
그래서 관련 없는 질문에서도 2~4위에 자주 끼어든다(q11, h12, 범위 밖 질문 o01·o02).
홀드아웃 h12("권한 검사를 프론트엔드에서만 하면?")는 유일하게 끝까지 틀린 문항인데, top-4 중 3개가 CSRF 문서였다.
용어사전에 "프론트엔드 → client-side"가 없는 것도 원인이다. 홀드아웃을 본 뒤에 추가하면 평가가 오염되므로 일부러 고치지 않았다.

**다음 단계:** 문서별 결과 수 상한(예: 문서당 2개) 또는 MMR로 결과를 다양화한다.

## 3. 오프라인 답변기가 '대응 방법' 대신 '문제 설명'을 발췌함

키워드 포함률(개발셋 0.77)을 깎은 주된 원인이다.
- q04 "SQL 인젝션 기본 방어는?"에 "문자열 연결을 쓰면 공격받는다"는 문장을 골라, 정작 "prepared statements"를 빠뜨렸다.
- q12(로그에 남기면 안 되는 데이터)와 q23(보안 설정 오류 예시)도 정답 문서는 찾았지만, 질문 의도와 다른 문장을 골랐다.

문장 발췌는 질문과의 임베딩 유사도만 보기 때문에 "무엇을 하라"와 "무엇이 위험하다"를 구분하지 못한다.
LLM 모드는 검색 결과를 읽고 다시 써서 이 문제를 줄이도록 설계했다.
오프라인 모드는 재현 가능한 하한선(baseline)으로 남겨 둔다.

**개선 이력:** 원문 마크다운이 줄바꿈으로 문장을 끊어 "control to ensure the integrity of the code flowing through the" 같은 조각이 발췌되던 버그를 수정했다(줄바꿈 이어 붙이기, 링크 문법 제거, "following:"으로 끝나는 머리 문장 제외).
그 결과 개발셋 citation precision이 0.85에서 0.88로 올랐다.

## 4. 평가 지표 자체의 한계

- **키워드 포함률**은 문자열 일치 검사라서 뜻은 맞아도 표현이 다르면 0점이다(예: "default accounts" 대신 다른 설정 오류를 예로 든 답변).
- **Faithfulness(proxy)**는 답변 문장과 근거 문장의 임베딩 유사도가 0.90 이상인지만 본다.
  음성 대조군(다른 질문의 근거와 짝지은 답변)에서는 1.1%만 통과해 오프라인 발췌 답변을 가려내는 데는 쓸 만하다.
  하지만 한국어로 바꿔 쓴 **틀린** 문장("비밀번호는 평문으로 저장해도 괜찮습니다")도 영문 근거와 0.86~0.88의 유사도를 보였다.
  즉 LLM이 생성한 답변의 사실 여부는 이 지표로 판단할 수 없고, `--judge`(LLM 판정)를 함께 써야 한다.
- **범위 밖 질문**이 2개뿐이라 거절 정확도 1.00은 참고용이다. 거절 임계값(0.78)도 이 2문항과 개발셋 최저 점수(0.80) 사이에서 정한 값이다.

## 5. 홀드아웃에서 hybrid가 오히려 낮았던 지표

홀드아웃 키워드 포함률은 dense 0.92, hybrid 0.83이었다.
hybrid가 검색 순위를 바꾸면서 발췌 문장이 달라진 탓이다(h06: 메타데이터 언급이 있는 조각의 순위가 밀림).
**검색이 좋아졌다고 답변이 항상 좋아지지는 않는다**는 점을 기록해 둔다.
